# 2026-09-29 · Mindcraft 部署起步与版本升级

## MC AI 伙伴（Mindcraft 部署）

- 目标：让 AI bot 以队友身份加入使用者的 Minecraft Java 存档
- 方案：Mindcraft（kolbytn/mindcraft）+ DeepSeek-V4.1-Flash（模型名 `deepseek-flash`）
- 位置：本仓库 `mindcraft/`
- 关键事实：
  - 起步时游戏为 Java 版 1.12.2（启动器 PCL2），而 Mindcraft 官方测试版本更高，存在兼容风险
  - DeepSeek 定价（2026-09 核实）：空闲时段 输入 ¥1/百万(未命中)、输出 ¥4/百万；高峰（工作日 9-12 / 14-18）翻倍。游戏时段多落在空闲价区间
  - 当时 hosts 把 GitHub 指向 127.0.0.1，直连失败 → 用 gh-proxy.com 镜像克隆成功
- 配置完成：`keys.json`（DeepSeek key）、`wb.json`（中文人格 + deepseek-flash）、`settings.js`（1.12.2 / 语言 zh-cn / port -1 自动扫描 / max_messages 8 / 危险编码关闭）
- embedding 陷阱：DeepSeek 无 embedding API，Mindcraft 会自动降级为词重叠匹配（`examples.js` 里 try-catch），不影响运行
- 踩坑：`node install` 不是有效命令，且管道后 `||` 兜底失效，导致后台依赖安装静默失败；重跑 `npm install` 解决
- API 连通性实测通过（deepseek-flash 回复正常）

## 排障过程（重要结论）

- 现象：bot 连接 compress 后被断，ECONNRESET。逐步定位：
  1. 名字校验：1.12.2 要求 3-16 字符，"WB" 非法 → 改成 3 字符合法名
  2. canvas 原生模块缺失（prismarine-viewer 依赖）：改 `agent.js` 为按需动态加载绕过
  3. LAN 会话失效：中途重开导致端口变化，netstat 验证后重开解决
  4. **根因：世界是 Forge 1.12.2（14.23.5.2864）+ mod**，FML 握手拒绝原版客户端
- FML 握手攻关：装 minecraft-protocol-forge（修了上游 undefined 枚举 bug），`tagHost \0FML\0` + 16 个 mod 列表握手成功，bot 进入 play 阶段；但服务器发 ServerHello 时崩 `Can't serialize unregistered packet`
- 源码级结论（读 Forge 1.12.2 源码确认）：`FMLProxyPacket` 需 `NetworkDispatcher` 转换为 vanilla 包，但 vanilla 编码器注册表里没有 `FMLProxyPacket` —— **Forge 1.12.2 的集成服务器 / LAN 对真 TCP 的非 Forge 客户端做 FML 握手，是官方未修 bug**（官方论坛、PojavLauncher #866 均有同款报告，专用服务器也随机出现）
- **最终方案**：用**原版 1.12.2 实例**打开同一存档开 LAN（mod 均为辅助类、无 mod 方块，原版可读），bot 走纯原版协议。`settings.js` 已加 `forge_server` 开关（默认 false），`mcdata.js` 支持 forge_handshake 自适应
- 教训：`node install` 静默失败坑；heredoc 中 `${}` 转义坑（改用 Write 工具写脚本）；PowerShell 输出不稳定时改用 Bash / netstat
