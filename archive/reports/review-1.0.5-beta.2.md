# 1.0.5-beta.2 审核与修复记录

日期：2026-11-14。审核基线：本地 1.0.5-beta.1 源码。

## 本轮发现并修复

| 问题 | 原来的影响 | 修复及验证 |
| --- | --- | --- |
| 配置恢复没有使用有效备份 | 主配置损坏后直接回到默认值，已经保存的模型、路径等设置丢失 | 校验上一份配置，自动恢复并持久写回；损坏文件保留。覆盖 JSON 损坏、分组结构错误和主文件缺失用例 |
| 重试同步使用当前所选整合包路径 | 停服后切换游戏目录，再重试同步，可能将旧世界放进新实例 | 按本次构建记录中的原游戏目录同步；原目录不存在时保留世界并给出明确提示。回归测试确认新实例没有新增 saves |
| 服务器副本继承旧运行标记 | 模板或 server-overrides 中的安全停服标记可能使新副本被误判为已保存 | 过滤运行会话、同步、基线和安全停服标记，保留原模板。覆盖模板和覆盖目录两种输入 |
| 异常退出记录尚未写完即可再次启动 | 旧进程关闭回调可能覆盖新一次启动的状态 | 完成退出记录前保持忙碌，拒绝并发启动；忽略已不属于当前进程的回调。加入延迟写入情况下的重入测试 |
| 切换实例保留旧版本、加载器和服务器模板 | Forge 切原版时仍可能使用 Forge；无法识别的新整合包可能沿用旧数据 | 用新实例检测结果完整替换相关字段，清空原世界和模板；未知加载器必须选择。手动修改游戏版本时重新匹配 Java 并清空旧加载器版本 |
| 模组缓存损坏后每次重试仍失败 | 校验失败仅报错，继续复用同一坏缓存 | 普通 Fabric 依赖和必要语音模组均保留坏缓存，再重新下载并校验。两条路径均有损坏缓存回归用例 |
| 状态读取失败或导航竞态 | 部分服务短暂失败可能影响整个向导；底部导航可绕过准备中的限制 | 非关键初始状态分别处理；轮询失败暂不显示旧的就绪状态，自动重试，避免重叠轮询；上下步按钮与侧栏使用一致的忙碌限制 |
| 版本标签写死 | 不同 beta 包显示同一个简略版本，难以判断是否更新 | 从实际应用版本读取完整版本号；冲突信息改为符合页面安全策略的样式类 |
| Java 错误说明固定为 1.20.1/Java 17 | 使用其他游戏版本时得到误导提示 | 改为提示核对当前 Minecraft、加载器和模组要求，再运行自动准备 |

## 已完成的验证

- 语法检查和 21 组自动化回归通过，新增上述配置恢复、跨实例同步、标记隔离、关闭竞态、缓存修复及界面状态用例。
- 隔离真实运行：Minecraft 1.21.11 + Fabric 0.20.1，服务器响应状态查询、唯一伙伴进服、语音 UDP 连接、管理员授予/撤销、正常停服均通过。测试关闭了单人世界导出，没有回写用户单人存档。
- Electron 隔离界面：冲突选择、恢复入口和完整版本显示通过。
- 桌面应用和伙伴生产依赖审计均为零项。
- 包内应用代码与最终源码一致；纯净配置检查通过。打包程序在全新的用户数据目录中启动成功，截图确认显示 `1.0.5-beta.2`，首次打开为模型配置向导。

## 尚未覆盖的范围

本轮没有验证所有游戏版本、所有第三方模组组合、外网隧道及麦克风双向语音。自动依赖补齐仍以来源可确认的 Fabric 项目和必要语音组件为主。世界内容模组的取舍仍由用户决定，不自动删除或降级内容模组，也不自动回退世界进度。

本轮交付本地安装包；尚未替换当前安装程序或发布到 GitHub。
